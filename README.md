# Учебный проект, посвященный сжатию текста при помощи авторегрессионной модели

**Репозиторий проекта (исходный код + инструкция):** https://github.com/Kiraprint/lstmcompressor_rsi

## Описание работы 
Данный проект реализует сжатие текста с использованием LSTM модели и адаптивного арифметического кодирования (ААК). 
В папке ./data/ находится текстовый файл enwik5 для сжатия, являющийся первыми 10^5 байтами enwiki-20060303-pages-articles.xml.

Kодировщик использует LSTM для вычисления вектора вероятностей следующего символа на основе предыдущих. Фактическое значение символа далее кодируется с помощью ААК. Затем веса модели обновляются. Это повторяется для всех символов файла.

Во время декодирования происходит симметричный процесс, декодирование с помощью ААК, предсказание символа при помощи LSTM, обновление модели и т.д.
Декодер работает симметрично, поэтому нет необходимости передавать параметры модели.

В качестве ААК используется реализация из https://github.com/nayuki/Reference-arithmetic-coding 

Параметры бейзлайна:
| Версия   | Исходный размер, байты | Размер после сжатия, байты | Коэффициент сжатия | Затраченное время, с |

| Baseline | 100000                 | 33326                      | 3.02               | 156                   |

### Измерено на этом устройстве (RTX 5090, CUDA 13.5)

| Версия | Исходный размер, байты | Размер после сжатия, байты | Коэффициент сжатия | Кодирование, с | Декодирование, с | Суммарно, с |
|---|---|---|---|---|---|---|
| Baseline (main.py, без изменений) — медиана 3 прогонов | 100000 | 33276 | 3.0052 | — | — | 18.1 (15.8–22.7) |
| **Финальное: GPT-2 приор (батч сегментов)** | 100000 | **14249** | **7.018** | 13.2 | 13.9 | **27.1** (26.9–30.1) |
| Self-contained: LSTM + Muon | 100000 | 32087 | 3.1165 | 20.0 | 16.1 | 36.1 (28.0–38.1) |

**Финальное решение** — замороженный GPT-2 как приор (arXiv:2407.07723, bellard.org/nncp):
коэффициент **7.018** (в 2.34× больше базового, **+133.5 %**), время
**27.1 с** против 18.1 с у базового — это
**1.49×** в парных замерах, то есть в бюджете +50 %
(граница 27.1 с). Токены — обратимый байтовый BPE (Latin-1, все 256 значений байт),
сегменты по 1000 токенов независимы и считаются одним GPU-батчем (в ≈20 раз быстрее
последовательного варианта, 170.6 с). Внутри сегмента токены идут строго
последовательно — параллельность только по измерению сегментов; свой KV-кэш у
каждого из 27 сегментов, а не у каждого токена. Порядок арифметического кодирования
position-major, поэтому декодер восстанавливает ту же историю. Плата за обрыв
контекста: 1.134 бит/байт при сегменте 1000, 1.125 при 1024 (предел позиционного
кодирования GPT-2), 1.181 при 512, 1.260 при 256. Модель и токенизатор — *фиксированные константы
алгоритма*, не получены предобработкой входного файла, поэтому требование «все
гиперпараметры предобработки файла в битстриме» выполнено (в потоке только длина и
число токенов). На held-out enwik8 (не контаминирован) — ratio 9.2–9.7.

**Self-contained вариант** — онлайн LSTM + Muon, не тянет внешних параметров:
**+3.7 %** (3.0052 → 3.1165), 36.1 с (1.77×
базового — бюджет +50 % он не выполняет), самообучается из файла. Оба варианта
восстанавливают файл байт-в-байт (MD5).

Время на этом хосте нестабильно: GPU делят посторонние процессы, одиночный замер
базового кодека давал от 15.8 до 32 с. Поэтому
`bench_timing.py` делает 3 чередующихся прогона (базовый → LSTM →
GPT-2) и считает парное отношение времени, при котором дрейф хоста сокращается;
результаты — в `timing_stats.json`, на графике точка = медиана, штрихи = прогоны.

Формат потока `NSCC1` помещает длину файла, маску алфавита и все гиперпараметры прямо
в заголовок, поэтому заранее знать тип файла не требуется.


## Описание задания к лабораторной работе
Улучшить код так, чтобы он:
- обеспечивал **улучшение коэффициента сжатия на 10%** при **росте временных затрат не более чем на 50%**. 

Можно улучшать следующие модули:
- Предобработка: замена слова из предварительно созданного словаря уникальным кодом, использование идеи из Byte-Pair Encoding токенизации и т.д.;
- Нейронная сеть: использование другой архитектуры (GRU, Transformer и др.), другой функции активации, изменениями связей между слоями и т.д.;
- Арифметический кодер: можно учесть возможную память источника, использовать другую оценку вероятностей и т.д.

Требования к реализации:
- Результаты должны быть продемонстрированы на enwik5 из папки ./data/;
- Восстановленый после сжатия файл должен полностью совпадать с оригинальным;
- В результатах приложить таблицу выше, обновив значения базового решения для вашего устройства и добавив строчку с улучшенным решением.
- Измерения времени кодирования и декодирования базовой и предложенной версии должны быть выполнены на одном и том же устройстве. 
- Алгоритм должен быть разработан при допущении, что не известно какого типа файл будет сжиматься (то есть все возможные гиперпараметры, полученные предобработкой входного файла, должны быть помещены в битовый поток)

## Просмотр ноутбука по LLM-кодеку

`llm_notebook.py` — отдельный marimo-ноутбук по GPT-2-приору: инвариант частот,
таблица записанных результатов, живой прогон `compress`/`decompress` со сверкой MD5,
проверка на произвольных байтах и интерактивный выбор длины сегмента (цена обрыва
контекста: 1.134 бит/байт при 1000 против 1.125 при 1024).

```bash
marimo edit llm_notebook.py     # локально
bash serve_llm.sh               # + публичный туннель cloudflared, печатает URL с токеном
MODE=run bash serve_llm.sh      # то же, но read-only (без правки кода)
```

Туннель требует `cloudflared` (`~/.local/bin/cloudflared`). Ссылка даёт полный доступ
к ядру ноутбука, поэтому токен и URL не публикуются, а сервер останавливается, когда
просмотр закончен.

## Запуск предложенной версии

Предложенный кодек лежит в `codec/` (модель `codec/nn.py`, статистическое смешивание
`codec/mixer.py`, оптимизатор `codec/optim.py`, поток `codec/core.py`, CLI `codec/cli.py`).

```bash
# 0. одна команда: окружение + зависимости + сжатие + распаковка + сверка MD5
bash run.sh                       # онлайн LSTM+Muon (self-contained)
bash run.sh data/enwik5 --llm     # GPT-2 приор (финальное решение)

# или вручную:
# 1. окружение
uv venv --python 3.12 .venv
uv pip install --python .venv torch --index-url https://download.pytorch.org/whl/cu128
uv pip install --python .venv -r requirements.txt

# 2. сжать + распаковать + сверка MD5 (config.json — итоговая конфигурация)
.venv/bin/python -m codec.cli --config config.json --input data/enwik5

# 3. маримо-ноутбук анализа (интерактивно)
.venv/bin/marimo edit notebook.py

# 4. отчёт и презентация (PDF, русский; typst)
.venv/bin/python make_figs.py && .venv/bin/python make_report.py   # -> report.pdf
.venv/bin/python make_slides.py && typst compile slides.typ slides.pdf  # -> slides.pdf
```

Итоговая конфигурация онлайн-кодека: `arch=lstm, n_streams=80, seq_len=32,
hidden=768, emb=150, optimizer=muon, muon_lr_scale=4.0, sched=cosine,
freq_scale=16000000`.

Деливераблы:

- `report.pdf` — отчёт на русском (`make_report.py` → typst).
- `slides.pdf` — презентация, 13 слайдов 16:9 (`make_slides.py` → typst).
- `notebook.py` — marimo-ноутбук анализа (формулы, абляции, графики).
