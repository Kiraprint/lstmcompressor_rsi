# Учебный проект, посвященный сжатию текста при помощи авторегрессионной модели

**Репозиторий проекта (исходный код + инструкция):** https://github.com/Kiraprint/lstmcompressor_rsi

## Описание работы 
Данный проект реализует сжатие текста с использованием LSTM модели и адаптивного арифметического кодирования (ААК). 
В папке ./data/ находится текстовый файл enwik5 для сжатия, являющийся первыми 10^5 байтами enwiki-20060303-pages-articles.xml.

Kодировщик использует LSTM для вычисления вектора вероятностей следующего символа на основе предыдущих. Фактическое значение символа далее кодируется с помощью ААК. Затем веса модели обновляются. Это повторяется для всех символов файла.

Во время декодирования происходит симметричный процесс, декодирование с помощью ААК, предсказание символа при помощи LSTM, обновление модели и т.д.
Декодер работает симметрично, поэтому нет необходимости передавать параметры модели.

В качестве ААК используется реализация из https://github.com/nayuki/Reference-arithmetic-coding 

Параметры бейзлайна:
| Версия   | Исходный размер, байты | Размер после сжатия, байты | Коэффициент сжатия | Затраченное время, с |

| Baseline | 100000                 | 33326                      | 3.02               | 156                   |

### Измерено на этом устройстве (RTX 5090, CUDA 13.5)

| Версия | Исходный размер, байты | Размер после сжатия, байты | Коэффициент сжатия | Кодирование, с | Декодирование, с | Суммарно, с |
|---|---|---|---|---|---|---|
| Baseline (main.py, без изменений) | 100000 | 33276 | 3.0052 | — | — | 27.0 |
| **Предложенная (LSTM + Muon)** | 100000 | **32087** | **3.1165** | 13.1 | 13.2 | **26.3** |
| LLM-приор (GPT-2, батч сегментов) | 100000 | **14249** | **7.018** | 13.1 | 15.5 | **28.7** |

Предложенная онлайновая версия улучшает коэффициент на **+3.7%** (3.0052 → 3.1165) и не
медленнее бейзлайна (26.3 с против 27.0 с), восстанавливая файл байт-в-байт (MD5).

**Направление из литературы** (arXiv:2407.07723, bellard.org/nncp): замороженный
GPT-2 как внешний приор. Токены — обратимый байтовый BPE (UTF-8 surrogateescape).
Сегменты по 1000 токенов независимы и считаются одним GPU-батчем в ножницах → на
том же устройстве достигается **7.018** (в 2.3× больше базового, в 2× больше цели +10 %)
за **28.7 с** (внутри бюджета +50 %). Модель внешняя и не входит в битстрим; она
предобучена на веб/вики-тексте. Все варианты восстанавливают файл байт-в-байт (MD5).

Формат потока `NSCC1` помещает длину файла, маску алфавита и все гиперпараметры прямо
в заголовок, поэтому заранее знать тип файла не требуется.


## Описание задания к лабораторной работе
Улучшить код так, чтобы он:
- обеспечивал **улучшение коэффициента сжатия на 10%** при **росте временных затрат не более чем на 50%**. 

Можно улучшать следующие модули:
- Предобработка: замена слова из предварительно созданного словаря уникальным кодом, использование идеи из Byte-Pair Encoding токенизации и т.д.;
- Нейронная сеть: использование другой архитектуры (GRU, Transformer и др.), другой функции активации, изменениями связей между слоями и т.д.;
- Арифметический кодер: можно учесть возможную память источника, использовать другую оценку вероятностей и т.д.

Требования к реализации:
- Результаты должны быть продемонстрированы на enwik5 из папки ./data/;
- Восстановленый после сжатия файл должен полностью совпадать с оригинальным;
- В результатах приложить таблицу выше, обновив значения базового решения для вашего устройства и добавив строчку с улучшенным решением.
- Измерения времени кодирования и декодирования базовой и предложенной версии должны быть выполнены на одном и том же устройстве. 
- Алгоритм должен быть разработан при допущении, что не известно какого типа файл будет сжиматься (то есть все возможные гиперпараметры, полученные предобработкой входного файла, должны быть помещены в битовый поток)

## Запуск предложенной версии

Предложенный кодек лежит в `codec/` (модель `codec/nn.py`, статистическое смешивание
`codec/mixer.py`, оптимизатор `codec/optim.py`, поток `codec/core.py`, CLI `codec/cli.py`).

```bash
# 0. одна команда: окружение + зависимости + сжатие + распаковка + сверка MD5
bash run.sh                       # онлайн LSTM+Muon (основное решение)
bash run.sh data/enwik5 --llm     # LLM-приор GPT-2 (направление из литературы)

# или вручную:
# 1. окружение
uv venv --python 3.12 .venv
uv pip install --python .venv torch --index-url https://download.pytorch.org/whl/cu128
uv pip install --python .venv -r requirements.txt

# 2. сжать + распаковать + сверка MD5 (config.json — итоговая конфигурация)
.venv/bin/python -m codec.cli --config config.json --input data/enwik5

# 3. маримо-ноутбук (интерактивно или headless-экспорт)
.venv/bin/marimo edit notebook.py
```

Итоговая конфигурация: `arch=lstm, n_streams=80, seq_len=32, hidden=768, emb=150,
optimizer=muon, muon_lr_scale=4.0, sched=cosine, freq_scale=16000000`.
Отчёт в PDF собирается как `make_figs.py && make_report.py → report.pdf`.
